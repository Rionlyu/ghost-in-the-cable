# API contract v1 (shared ownership: parent only)
Backend at http://127.0.0.1:8000, Vite dev port5173 proxy /api. Final production one-port at8000 serves web/dist. IDs unguessable secrets.token_urlsafe. JSON snake_case.

GET /api/meta -> {title:string, faults:[{id:"I"|"X"|"Z"|"Y",name:string,description:string}], tools:[{id:"z"|"x"|"bell",name:string,description:string,measurement_hint:string,cost_tokens:0|1}]}
POST /api/shifts body {} (default story) or {route:"story"|"bits"|"phase"|"entanglement"} -> Shift. Strict forbidden extras; route selection starts a new session.

POST /api/shifts/{id}/probe body {tool:"z"|"x"|"bell",expected_revision:integer>=0} -> Shift
POST /api/shifts/{id}/diagnose body {fault:"I"|"X"|"Z"|"Y",expected_revision:integer>=0} -> Shift
POST /api/shifts/{id}/next body {expected_revision:integer>=0} -> Shift
GET /api/shifts/{id}/report -> full resolved final report JSON, only after phase complete, otherwise409
GET /api/evidence -> {kind:"exact-statevector",conditions:string,unassisted_bound:0.5,entangled_ideal:1.0,mappings:[{fault:string,z:{[bits:string]:number},x:{[bits:string]:number},bell:{[bits:string]:number}}],sources:[{title:string,url:string}],limitations:string[]}

POST /api/training/probe body {tool:"z"|"x"|"bell",fault:"I"|"X"|"Z"|"Y"} -> TrainingProbeResponse. Stateless resettable KNOWN training cable, not a customer-session mutation. Strict forbidden extras, including shift IDs, seeds, shots, circuit definitions and expected_revision. Each accepted request executes the real engine once and exposes only the selected public training fault/circuit. It never reads, creates or modifies a game session. Simulator or invalid-result failures return503 without an invented reading. Same API no-store/security headers apply.
TrainingProbeResponse={kind:"training",known_fault:Fault,reading:Reading,circuit_text:string,gates:Gate[],probabilities:{[bits:string]:number},probe_marginal:{"0":number,"1":number},reference_marginal:{"0":number,"1":number}|null}. Reading/Gate fields are explicitly allowlisted. Four-cable comparison means four separate resettable training experiments, not four uses of a concealed customer device. Ordinary customer faults/circuits remain secret until diagnosis.

History={ticket_id:string,title:string,tool:Tool,bits:string,fault:Fault,guess:Fault,correct:boolean,delta:number}

Server state rules: default story suspect families by ticket index IX, IZ, IXYZ, IX, IXYZ, IZ, IXYZ, IX (3 full-family jobs). Routes are frozen on session creation: story uses all eight existing tickets; bits uses porchlight/skeleton-sign/dawn-bell (3); phase uses whisperphone/moon-radio (2); entanglement uses mirror-organ/fog-machine/midnight-projector (3). Initial reference tokens: 3 for story/entanglement, 0 otherwise. Every transition and export follows the selected route, with actual ticket_count and complete reports for every length. Secrets choose within family, not serialized before resolved. Initial credits0; correct adds reward, incorrect subtracts penalty (negative credits okay). Bell consumes1 token when successful probe accepted; other probes free. POST probe exactly once -> diagnose; POST diagnose once -> resolved; POST next only from resolved -> next choose_tool or complete after the route's final ticket. Locks enforce concurrent requests. Every probe/diagnose/next requires a strict nonnegative integer expected_revision (missing, null, booleans, strings, floats and negative values are422; no legacy bypass). Under the same lock, compare expected_revision to Shift.revision before phase checks, simulation, token expenditure, scoring or history changes; any mismatch is409 with no game-state change. Revision starts at0 and increments exactly once on each successful probe, diagnose and next, including the final completion transition; failed actions and GET never increment it. A full completed eight-ticket shift has revision24. The client captures its currently rendered revision in each mutation payload; after409 it refreshes the shift for review and never automatically retries the old action or replaces its captured revision. This rejects delayed cross-ticket/tab actions even when a later ticket has the same phase. Create allows only optional route (default story); arbitrary tickets, faults, seeds and extra fields remain forbidden. Recovery GET returns same reading; user may reset with new shift but no reroll within a ticket. Unknown id404, invalid body422, illegal transition409. Pydantic fields forbid extras. Fault guess must be in ticket suspects. No secret seed/admin route/fault/debug circuit in live pre-diagnosis response. History only resolved jobs. Idle-local sessions bounded/expire and explicit state-lost recovery. Unreachable backend must show actual error and retry, never client-synthesize results.

Physics: z tool |0>--fault--measure, x tool |0>--H--fault--H--measure, bell H(q0),CX(q0,q1), hidden fault(q0), CX(q0,q1),H(q0), measure q0->c0,q1->c1. Display bits c1c0 (reference then probe). Literal mappings independent fixture: I z0 x0 bell00; X z1 x0 bell10; Z z0 x1 bell01; Y z1 x1 bell11. Bell marginals refer to state immediately after device BEFORE decoding, each1/2, not final measured marginals. Gates metadata exclude measurement? include all gates with readable labels; circuit_text actual Qiskit drawing after resolution. Frontend can explain mapping before probe, but hidden fault revealed only after diagnosis.

Production: errors JSON {detail:string} (422 may be standard Pydantic detail array). No wildcard CORS; same origin. Loopback host default. Bare UI route GET fallback only (must not swallow unknown /api paths). Basic no-store JSON and CSP/security headers where compatible with Vite prod. Frontend persists only shift ID in localStorage, no personal information. Evidence is exact circuit-derived probabilities, not empirical run or hardware result.
